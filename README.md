**报告日期**:2026-09-05

**设备机主**:Aviiya(设备自带名称)

## 2. 故障现象

1. **NFC 无法使用**:打开 NFC 应用时,转圈(沙漏)数秒后弹出错误屏:
   - 英文固件:`Error: NFC Chip Failed`
   - 汉化固件:`错误:NFC芯片故障`
2. 现象持续、稳定复现;偶发(极低概率)在重启后可短暂恢复,恢复期间读卡功能完整,随后又失效。
3. 附带问题(另行检测,详见 §6):Sub-GHz、RFID 等部分工具使用中偶发卡死/崩溃,该现象在**使用者自行更换的 SD 卡与自行混装系统**下观察,与本报告 NFC 主诉相互独立。

## 3. 检测方法与过程

### 3.1 判定依据(固件对 NFC 芯片的检测逻辑)

固件开机及每次进入 NFC 应用时,会通过 SPI 总线读取 NFC 芯片 **ST25R3916** 的身份寄存器 `IC_IDENTITY (0x3F)`:

- 正常读取值应为 `0x28`(芯片类型号匹配);
- 读取结果错误时,日志输出 `Wrong chip id`,NFC 应用直接进入故障屏。

本次检测在固件内加入了诊断日志,可输出**每次读取到的原始字节值**,用于区分“芯片未供电/未响应 / 芯片型号不同 / 总线异常”等不同故障。

### 3.2 固件对照测试矩阵

在设备上依次刷入并测试了 **3 个不同固件**,NFC 驱动层代码在三个固件中完全相同或同源:

| # | 固件 | 版本/来源 | 构建时间 | 测试次数 | 芯片 ID 读取结果 | NFC 状态 |
|---|---|---|---|---|---|---|
| 1 | Momentum 官方上游基底 + 诊断补丁(自编译) | 基底 commit `6c12582f` | 2026-09-04 自编译 | 3+ 次开机、4+ 次应用打开 | 恒 `0xFF`(8 次开机重试全覆盖) | 全部报错 |
| 2 | 汉化版 `MNTM-009CN`(此前机内固件,**使用者自备**;设备当时为**使用者自行混装**状态:009 固件 + 012 应用包) | commit `6c12582f`(dirty) | 2025-03-01 | 3 次应用打开 | `Wrong chip id`(原始值未见) | 全部报错 |
| 3 | 较新固件 `mntm-012`(**使用者自备**,测试时干净整包刷入,固件与应用同版本配套) | commit `e1784e74`(clean) | 2025-12-31 | 1 次开机、4 次应用打开 | `Wrong chip id` | 全部报错 |

> 说明:本设备上测试用的**所有固件均由使用者自行获取/刷写,非商家提供**。三个固件的 NFC 驱动代码同源,均复现同一故障。

> 固件 1 中加入了“开机 8 次重试、延时递增至 500ms”及“应用打开时对芯片执行复位命令后重读”的诊断逻辑,仍全部失败。

(4 次打开 NFC 应用,均报错;屏幕同步显示 `Error: NFC Chip Failed`。)

## 4. 分析

1. **读取恒为 0xFF 的含义**:SPI 总线上 MISO 数据线保持高电平空闲、芯片完全没有驱动总线 —— 即 **MCU 侧根本“看不到”NFC 芯片**。典型原因按概率排序:
   - NFC 芯片供电缺失或供电不稳定;
   - NFC 芯片处于持续复位状态(复位电路不良/虚焊);
   - NFC 芯片本体损坏或焊接不良(虚焊/开裂);
   - NFC 芯片与 MCU 之间的 SPI 连接(CS/SCK/MOSI/MISO)存在接触不良。
2. **可排除固件原因的证据**:
   - 三个不同来源/版本的固件(NFC 驱动逻辑同源)全部失败;
   - 其中较新的 mntm-012 固件(2025-12-31 构建)同样失败 —— 若为固件缺陷,更晚近的固件理应修复或至少表现不同;
   - 诊断固件已覆盖“上电后 ~1 秒内 8 次递增延时重试”与“复位命令后重读”,芯片始终无响应;
   - 固件中不存在对 NFC 芯片供电/复位引脚的控制逻辑(该芯片在原厂设计中由常供 3.3V 直接供电,无可软件控制的电源开关),故不存在“固件没开电源”的可能。
3. **“偶发恢复”的解释**:极低概率的间歇性恢复,与**接触不良/虚焊类硬件缺陷**的典型表现一致(温度、形变、振动导致接触状态变化),而非软件状态问题。

## 5. 结论

**NFC 芯片在固件层面完全不可见(持续读取为 0xFF/无响应),经多固件、多轮重启、寄存器级诊断确认,判定为硬件故障,固件无法修复。**

建议商家:
1. 优先检查 NFC 芯片供电与复位电路、芯片焊接(可热风补焊/显微镜检查);
2. 必要时更换 NFC 芯片或整板;
3. 修复后请验证:连续读取 `IC_IDENTITY` 寄存器稳定返回 `0x28`,并可正常完成 ISO14443A 读卡流程。

## 6. 附带发现(非本次主诉,与 NFC 结论相互独立)

- **工具卡死/崩溃**:Sub-GHz、RFID 等工具偶发卡死/崩溃。需说明:该现象在**使用者自备 SD 卡 + 自行混装的固件/应用组合**(009 固件 + 012 应用包)条件下观察,期间该 SD 卡还出现目录读取偶发错误(`file/dir not exist` 等),与应用崩溃高度相关。此类问题与 NFC 主诉**相互独立**;如需复测,可在商家认可的软硬件状态下进行。

## 7. 检测环境附录

- 检测工具:USB 串口 CLI + 固件内诊断日志(未拆机、未改动任何硬件)
- 设备状态:检测前后硬件无任何改动;SD 卡中固件包 `f7-update-mntm-012` 完好保留,可随时恢复
- 环境说明:设备上所有固件均由**使用者自行获取/刷写**(含“混装”组合与自备 SD 卡),商家未提供任何固件;NFC 主诉结论基于干净整包固件(mntm-012)等多次对照,不受上述因素影响
- 日志原始文件可应商家要求提供
